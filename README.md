# concert-watch

공연 곡목을 추적해서 슬랙으로 알려주는 도구.

KOPIS로 **전국** 클래식 공연을 전수 수집하고, 공연장 상세페이지에서 **곡목**을
긁어와 관심목록과 대조한다. 새로 뜬 공연만 알림이 나간다.

```
KOPIS 공연목록 (전국, 클래식)        언제 / 어디서 / 누가 / 가격
   +                                 ※ 곡목은 안 준다 (sty 필드가 비어 있음)
예술의전당 dataList  → 상세 크롤링 → 곡목
롯데콘서트홀 캘린더 API              (곡목은 포스터 이미지 안이라 목록까지만)
        ▼
   SQLite (concerts.db)  ← 필터 없이 전국 전부 저장. 중복은 조회 시점에 병합
        ▼
   watchlist.yml 매칭 (작곡가 AND 장르 AND 번호 + 근접 조건 + 약력 배제)
        ▼
   슬랙 웹훅 / 콘솔  (관심 지역 우선 정렬)
```

## 설치

```bash
pip install -r requirements.txt
cp .env.example .env      # KOPIS_KEY 채우기
```

`truststore`는 선택이 아니다. 사내 TLS 검사 프록시가 있는 PC에서는 이게 없으면
`requests`가 `self-signed certificate in certificate chain`으로 전부 실패한다.

## 사용

```bash
python -m concert_watch sync                # 수집 + 보강 + 매칭 + 알림
python -m concert_watch sync --dry-run      # 알림 기록을 남기지 않고 확인만
python -m concert_watch sync --resend       # 이미 보낸 것도 다시 발송
python -m concert_watch matches             # 현재 매칭 전체 보기
python -m concert_watch matches --weekend   # 주말(토·일) 공연만
python -m concert_watch search 브람스        # 로컬 DB 자유 검색
python -m concert_watch search 브람스 --weekend
python -m concert_watch slack-test          # 슬랙 연결 점검
```

`search`는 수집된 모든 공연을 대상으로 한다. 관심목록에 없어도 검색된다.

## 관심목록 (`watchlist.yml`)

```yaml
watches:
  - name: 라흐마니노프 피아노 협주곡 2번
    all:
      - [라흐마니노프, Rachmaninoff, Rachmaninov]        # 그룹 안 = OR
      - [협주곡 2번, "Concerto No. 2", "Op. 18"]         # 그룹 끼리 = AND
    window: 80        # 그룹들이 이 글자 수 안에 모여 있어야 함 (0이면 조건 없음)
```

`window`가 핵심이다. 없으면 이런 게 걸린다:

```
Robert Schumann - Arabeske, Op. 18            ← Op.18
Sergei Rachmaninoff - Two Pieces...           ← 라흐마니노프
```

둘 다 문서에 있지만 서로 다른 곡이다. 곡목은 보통 `작곡가 — 작품명 Op.번호`가
한 줄에 붙어 나오므로, 좁은 창 안에 함께 있는지를 보면 걸러진다.

## 슬랙 연결

두 가지 방식을 지원한다. 봇 토큰이 설정돼 있으면 그쪽을 먼저 쓴다.

### 봇 토큰 (현재 사용 중)

```
SLACK_BOT_TOKEN=xoxb-...
SLACK_CHANNEL=#classic_search
```

필요한 스코프는 `chat:write`. 여기에 **`chat:write.public`이 있으면 공개 채널은
봇을 초대하지 않아도 바로 쓸 수 있다.** 비공개 채널이면 채널에서 `/invite @봇이름`.

`SLACK_APP_TOKEN`(`xapp-`)은 Socket Mode 전용이라 알림만 보낼 거면 필요 없다.
슬랙에서 `/공연 브람스` 같은 검색까지 하고 싶어질 때 쓴다.

### 웹훅 (대안)

```
SLACK_WEBHOOK=https://hooks.slack.com/services/...
```

api.slack.com/apps → 앱 선택 → Incoming Webhooks → On → Add New Webhook to Workspace.

### 점검

```bash
python -m concert_watch slack-test                          # .env의 채널로
python -m concert_watch slack-test --channel "#다른채널"
```

흔한 실패:

| 오류 | 원인 |
|---|---|
| `not_in_channel` | 비공개 채널. `/invite @봇이름` |
| `channel_not_found` | 채널명 오타 |
| `missing_scope` | OAuth & Permissions에서 `chat:write` 추가 후 앱 재설치 |

> **토큰은 자격증명이다.** `.env`는 `.gitignore`에 들어 있지만, 토큰이 어딘가
> 노출됐다면 api.slack.com/apps → OAuth & Permissions → Regenerate 로 재발급한다.

## 관심 지역 (`REGION_PRIORITY`)

**필터가 아니라 우선순위다.** 전국을 그대로 수집하고, 이 지역을
(1) 곡목 보강 크롤링에서 먼저 처리하고 (2) 결과 목록 위쪽에 배치한다.
여기 없는 지역도 수집되고 알림도 간다.

```
REGION_PRIORITY=서울특별시,경기도,인천광역시,대전광역시,세종특별자치시,충청남도,충청북도
```

## 중복 병합 — 고르지 않고 합친다

같은 공연이 여러 소스에 잡힌다. 소스마다 아는 게 다르므로 **하나를 고르면 정보를 잃는다.**

| 소스 | 곡목 | 출연진 | 시간 | 가격 |
|---|:--:|:--:|:--:|:--:|
| 예술의전당 | ✅ | — | ✅ | ✅ |
| 롯데콘서트홀 | — | — | — | — |
| KOPIS | — | ✅ | ✅ | ✅ |

그래서 `_dedupe`는 대표 행을 고른 뒤 **빈 필드를 다른 행에서 채운다.**
덕분에 롯데 공연도 KOPIS가 아는 출연진·시간·가격을 갖는다.

같은 공연인지 판정하는 기준은 **(공연장, 날짜) + 제목 유사도**다:

- 공연장 이름은 `[서울]` 같은 지역 꼬리표를 떼고 비교한다.
  KOPIS는 `예술의전당 [서울]`로 주는데, 이걸 안 떼면 예당 공연 142건이
  `예술의전당`과 따로 놀며 중복으로 남는다.
- 제목은 앞부분 비교로는 부족하다. 어순이 바뀌거나(`KBS교향악단 제830회` /
  `제830회 KBS교향악단`) 부제가 붙는다(`한국 가곡의 밤` / `한국 가곡의 밤: 우리 가곡…`).
  `difflib` 유사도 `TITLE_SIM=0.4`를 쓴다 — 실측상 같은 공연은 0.44~1.00,
  다른 공연은 0.00~0.06이라 사이가 넉넉하다.
- **날짜·장소만으로 합치면 안 된다.** 같은 홀에서 하루에 마티네와 정기연주회가
  따로 열린다 (2026-09-10 롯데).

## 주말·공휴일 강조

쉬는 날에 열리는 공연을 표시한다. 공휴일은 주말과 **구분해서** 보여준다.

| | 콘솔 | 슬랙 | 예시 |
|---|:--:|:--:|---|
| 주말 | `★` | 🟠 | `★ 2026-10-24(토) 17:00 · 아트센터 인천` |
| 공휴일 | `◆` | 🔴 | `◆ 2026-09-24(목) 추석 연휴 19:30 · 롯데콘서트홀` |

공휴일은 이름까지 붙는다. 개천절이 토요일이면 '토요일'보다 '개천절'이 정보량이
많으므로 공휴일 표시가 주말보다 우선한다. 머리말에 건수도 따로 낸다:
`🎹 새 공연 13건 (🟠 주말 6건 · 🔴 공휴일 1건)`

`--weekend`를 붙이면 주말·공휴일 공연만 남는다.

### 판정 규칙

- 여러 날 공연은 **하루라도 걸리면** 그 종류로 친다. 평일 저녁에 못 가는
  사람에게 중요한 건 '갈 수 있느냐'지 시작일이 무슨 요일이냐가 아니다.
- 단 **7일을 넘는 공연은 표시하지 않는다**(`MAX_SPAN_FOR_MARK`). 몇 달짜리
  전시·장기공연은 어차피 모든 주말·공휴일에 걸쳐서 표시가 정보가 안 된다.
  실제로 4개월짜리 전시가 '신정 공연'으로 잡히는 걸 보고 넣은 제한이다.

### 공휴일 표 갱신

`concert_watch/holidays.py`의 `HOLIDAYS`에 날짜만 추가하면 된다.
음력(설날·추석·부처님오신날)과 대체공휴일 때문에 계산으로 못 뽑아서 표로 들고 있다.
현재 **2026~2027년**이 들어 있다. 표에 없는 연도는 '공휴일 아님'이 아니라
'모름'이므로, 해가 바뀌기 전에 채워야 한다.

대체공휴일 규칙(검증에 사용):
- 공휴일이 토·일과 겹치면 다음 평일이 대체공휴일
- **현충일은 예외** — 겹쳐도 대체공휴일이 없다
- 설날·추석 연휴는 **일요일**과 겹칠 때만 대체공휴일이 생긴다
  (2026 추석은 목·금·토라 대체공휴일이 없다)

## 시간·요일

- 요일은 저장하지 않고 `date_from`에서 계산한다. 소스가 주든 말든 항상 나온다.
- KOPIS `dtguidance`는 `금요일(19:30)` 형태라 요일이 겹친다. 하루짜리 공연이면
  시각만 남기고, 여러 날 공연(`금요일(19:00), 토요일(19:00)`)은 요일이 정보라 그대로 둔다.
- 예당 목록 API는 시간을 안 준다. 상세페이지의 `시간 / 19:30` 라벨-값 쌍에서 뽑는다
  (`sac.parse_fields`). 이미 받아둔 본문에서 재파싱하려면 `python backfill_time.py`.
- 여러 날 공연(뮤지컬·무용·연극)은 단일 시간이 없고 회차표라 비어 있다. 정상이다.

## 오탐을 막는 세 장치

곡목 텍스트에는 이번 공연의 곡목만 있는 게 아니다. 연주자 약력, 다른 작곡가의
작품번호가 섞여 있어서 단순 포함검사로는 오탐이 쏟아진다. 실제로 겪은 것들:

| 장치 | 막는 것 | 실제 사례 |
|---|---|---|
| `program_core` (sources/sac.py) | 곡목 구간만 잘라내 약력 배제 | "BBC 심포니와 연주한 라흐마니노프 협주곡 2번 **음반**" |
| `window` (match.py) | 멀리 떨어진 항끼리 결합 | 슈만 `Arabeske Op.18` + 다른 줄의 라흐마니노프 |
| `exclude` (match.py) | 구간 분리 실패 시 2차 방어 | "협주곡 전곡을 편곡해 **완주했으며**" |

`exclude`는 기본값(`BIO_MARKERS`)이 적용된다. 끄려면 watchlist 항목에
`exclude: false`를 쓴다.

## 놓치기 쉬운 것: 번호를 안 쓰는 공연

`라흐마니노프 3개의 피아노 협주곡` 같은 전곡 공연은 제목에 "2번/3번"이 없어서
번호 기반 항목에 안 걸린다. 정작 가장 보고 싶은 공연인 경우가 많으므로
전곡·묶음 항목을 따로 두는 편이 좋다 (watchlist.yml 참고).

## 알아둘 것

- **KOPIS에는 곡목이 없다.** `sty`(소개글) 필드는 실측 결과 항상 비어 있었다.
  곡목은 공연장별 크롤링으로만 얻는다. **현재 곡목이 있는 곳은 예술의전당뿐이다.**
- 따라서 **예당 밖 공연은 공연명·출연진으로만 매칭된다.** 곡목이 제목에 없으면
  놓칠 수 있다.
- **수집 단계에서는 중복을 버리지 않는다.** 롯데 자체 캘린더는 기획공연만 싣고
  대관공연을 빠뜨려서(자체 35건 vs KOPIS 46건), 전용 소스를 우선하면 오히려
  공연을 잃는다. 전부 저장하고 조회 시점에 병합한다.
- 인터파크(NOL 티켓)는 붙이지 않았다. 비공개 API가 두 번째 요청에서 403을 냈다.
- 세종문화회관 자체 목록 API(`performListData.do`)는 502를 반환한다. KOPIS로 대체된다.
- 롯데콘서트홀 상세페이지는 곡목이 포스터 이미지 안에만 있다 (OCR 필요).
- KOPIS는 티켓 판매 집계 기반이라 무료·소규모 공연이 누락될 수 있다.
- 크롤링은 호스트당 1초 간격을 지킨다 (`net.MIN_INTERVAL`).
- 데이터 출처: KOPIS (KOGL 제1유형, 출처 표시 시 자유 이용).
